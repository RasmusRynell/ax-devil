# Test fixtures

Committed test inputs, shared by Rust and frontend tests. Each one records where it came from and its license.

| File | Source | License |
|------|--------|---------|
| `decoders/onvif_xml/sample_frame.xml` | One ONVIF analytics scene-description frame, carried unchanged from `tests/plugins/decoders/onvif_xml/data/` at the reference commit (`docs/rebuild/README.md`) | Repository license (MIT) |
| `decoders/onvif_xml/frames.xml` | Written by hand for `crates/scene-decoders/tests/onvif_xml.rs`: three documents among blank, whitespace-only and CRLF lines, one nested in a metadata stream and one malformed | Generated for this repository (MIT) |
| `decoders/cvat/sample.xml` | A two-frame CVAT task with a box track and a polygon track, carried unchanged from `tests/plugins/decoders/cvat/sample_data.py` at the reference commit (`docs/rebuild/README.md`) | Repository license (MIT) |
| `video/cfr_h264_gop10_bf2.mp4` | Generated by `video/generate.sh` (FFmpeg n9.0.2, libx264) from a synthetic flat-luma source: 64x48, 30 fps, 90 frames, GOP 10, two B-frames | Generated for this repository (MIT) |
| `video/long_gop_h264.mp4` | Same generator: GOP 60, 180 frames | Generated for this repository (MIT) |
| `video/open_gop_h264.mkv` | Same generator: x264 open GOP, 90 frames, GOP 30, three B-frames | Generated for this repository (MIT) |
| `video/vfr_h264.mkv` | Same generator: frame N shown at 33 N + 17 floor(N / 10) ms, 60 frames | Generated for this repository (MIT) |
| `video/hevc_gop30.mp4` | Same generator, libx265: 90 frames, GOP 30 | Generated for this repository (MIT) |
| `video/pts_offset.mp4` | Same generator: 60 frames, `-output_ts_offset 10`, so the container starts at 10 s | Generated for this repository (MIT) |
| `video/truncated.mp4` | `cfr_h264_gop10_bf2.mp4` with its last 30 bytes cut off by `generate.sh` | Generated for this repository (MIT) |
| `video/not_video.mp4` | A line of text named like a video, written by `generate.sh` | Generated for this repository (MIT) |
| `video/yuv444p10_w18.mkv`, `video/rgb24_w16.nut` | Same generator: four frames of one flat colour as 10-bit 4:4:4 BT.709 at width 18, and as raw RGB24 at width 16 | Generated for this repository (MIT) |
| `video/seq/000001.jpg` to `000012.jpg` | Same generator: an image sequence of 12 flat-luma JPEGs, 64x48, numbered from 1; image k has luma 7 (k - 1) | Generated for this repository (MIT) |
| `datasets/mot/` | A MOT Challenge dataset written by `datasets/mot/generate.sh`: `train/MINI-01-DPM` (images, det with one malformed row, gt with classes 1, 7 and 99), `train/MINI-01-FRCNN` (det only) and `test/MINI-02` (images, det); 12 frames of 64x48 at 10 fps with no rows on frame 6. Images are copies of `video/seq/` | Generated for this repository (MIT) |
| `settings/v1.json` | Settings file as version 1 wrote it, with entries a later version does not know; every `v<N>.json` must still load (`crates/settings/README.md`) | Generated for this repository (MIT) |
| `shortcuts/keys.json` | Shortcut spellings and their canonical form or rejection, read by `crates/settings` and `frontend/src/kit/shortcut.test.ts` | Generated for this repository (MIT) |

Frame N of each luma-coded video is flat with luma (7 N) mod 256 (see the header of `video/generate.sh`), so a test
can tell which frame it decoded. Regenerate with `fixtures/video/generate.sh` (then `fixtures/datasets/mot/generate.sh`, which copies its images); it needs FFmpeg with libx264 and
libx265 and gives the same bytes on every run of one FFmpeg build.

Oracle fixtures generated at the reference commit add their provenance here ([09](../docs/rebuild/09-testing.md#oracle-policy)).
