# Draw System Architecture

The Scene draw system is two halves with one boundary between them. This page is that boundary; each half's own
rules are in its README.

## Core Ownership

`ax_devil.modules.scene.rendering` owns semantic rendering. It knows about `Scene`, `Entity`, `Observation`,
`Classification`, filters, draw recipes, catalog JSON, template compilation, and hover target indexing. See the
[rendering README](../../src/ax_devil/modules/scene/rendering/README.md).

`ax_devil.modules.video_player` owns generic drawing. It knows about video frames, prepared geometry, paths and
glyphs, Qt Quick display and image export, viewport math, hover card placement, and metrics collection. It must not
become Scene-aware. See the [video player README](../../src/ax_devil/modules/video_player/README.md).

The boundary object is `VideoOverlayData`. Scene code supplies a `drawing_generator`, `interaction_provider`, and
`metrics_provider`; the video player calls those protocols without knowing what domain object produced them. The
`DrawingTarget` contract accepts batches of catalog-resolved boxes, circles, lines, points, polygons, polylines, texts
and labels, where row i of every argument describes one primitive and a `Paint` carries each style field as one
shared value or one value per row. Catalog instructions resolve normalized coordinates straight into final backend
data; there is no intermediate primitive list.

## Runtime Flow

```text
FrameData + OverlayData(Scene)
  -> SceneFramePresenter.prepare_frame(...)            video_viewer: retains one CachedSceneOverlay per Scene identity
  -> VideoFrameWithOverlays + VideoOverlayData
  -> FrameDisplay.display_frame(...)
  -> VideoFrameRenderer                                 video_player: GUI-thread preparation, coalesced to latest frame
  -> CachedSceneOverlay.prepare_drawing(RenderContext, DrawingBuffer)
       -> optional filter -> SceneRenderCatalog.render_scene(...)
       -> one generated update function per recipe evaluates all its rows at once
       -> batches of primitives for rows that completed without failures
  -> DrawingBuffer prepares each queued primitive kind once at finish() (labels as they arrive)
  -> PreparedDrawing (vertex bytes, resolved paths, shaped glyphs, label sprites)
  -> QuickOverlay binds changed items to the retained Qt Quick scene graph
```

Live and offline viewers differ only in how they obtain `FrameData` and `OverlayData`; both converge on
`SceneFramePresenter`. The presenter attaches the active catalog through a provider callback as well as a value, so an
already-created overlay sees a newly selected catalog before the next frame is built. `FrameImageRenderer` runs the
same path on a non-visible surface for export, at native source resolution.

Rendering diagnostics flow the other way: `CachedSceneOverlay` reports preparation metrics through the overlay
protocol and `VideoFrameRenderer` records one paint sample per preparation; the
[diagnostics README](../../src/ax_devil/modules/diagnostics/README.md#measurement-definitions) defines the boundaries.

## Catalogs And Their Users

Render catalogs are JSON edited outside the app, usually by an agent following the
[render-catalog skill](../../.agents/skills/render-catalog/SKILL.md); the language reference is generated by
`ax-devil catalog reference`. `SceneRenderCatalogManager` is created once in `Application.run()` and passed down to
every viewer, media panel, selector and the [catalog viewer](catalog-viewer.md); it owns discovery, compiled reuse and
file watching, while each view holds a `SceneRenderCatalogSelection`. Rules that cross this boundary (read-only
built-ins, the default catalog, per-view visibility, failed loads) are in
[Rendering invariants](../domain/invariants.md#rendering).

## Extension Points

- Change a shipped look: edit the built-in catalog JSON; touch the schema only if the shape changes.
- Expose more Scene data to recipes: add typed inputs in `scene/rendering/catalog.py`, then schema and compiler tests.
- Add a drawing primitive: extend `DrawingTarget` and `DrawingBuffer` in `video_player/engine`, declare its fields in
  `PRIMITIVES`, emit it in `template_runtime/executable.py`, regenerate the schema.
- Add a user-selectable detail: extend `OverlayFeature`, tag the catalog components, regenerate the schema.
