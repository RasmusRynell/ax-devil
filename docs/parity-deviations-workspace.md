# Parity deviations: workspace, sidebar and live

Where the workspace, sidebar and live [parity](parity.md) rows differ from the reference. The rest are in
[parity deviations](parity-deviations.md).

| Row | Deviation | Reason |
|-----|-----------|--------|
| WS-13 | A window lays out at most 8 panes, and a ninth is refused with a message; the reference has no limit | A seat holds at most 8 streams, and every pane streams |
| WS-13 | An item opened by anything but Open (Add Video, the command line, another seat) gets a preview pane beside the largest one; the reference replaced the active preview | A window shows every open item; a window with several to place would otherwise keep only the last |
| WS-13 | Opening what the front pane already shows (the same item and entry) changes nothing; the reference opened it again, replacing the preview or adding a pane | A second open of the same row would restart the frame and the clock on screen |
| LV-01 to LV-08 | Closed on fake-transport evidence. Not verified: a real camera session, a real DataHub, and the order of MQTT cleanup at quit against a real camera. [human] "just do the tests reasonable if we even need them, then just assume it works... we are shutting down anyways" | Owner decision; the fake RTSP, MQTT, DataHub and VAPIX servers and the quit test cover the behavior |
| WS-01 | Adding an item whose id is already in the workspace replaces it in place; the reference raised "Workspace items must have unique ids." `[AI]` | Ids are generated, so a user cannot reach it |
| WS-01 | `with_label` (`intake.rs`) trims every item label, whoever sets it; the reference trimmed only in its rename dialog `[AI]` | One rule for naming an item |
| WS-06 | An item with a viewer open is not resolved again when its files change: its rows keep the old Content until the user reloads; the reference refreshed the rows at once and kept the viewer on its old Content | A stream ends with the generation of its Content |
| WS-06 | The files are polled once a second, a change reported when it looked the same twice in a row (the reference used file events and a 1 s quiet timer), so changes on network shares are noticed too | Polling needs no dependency (as the catalog folder) |
| WS-06 | A plugin resolver's `watch` operation names files only, and only a plugin whose manifest says `watches` is asked, at the cost of one more process per resolve; the reference's `source_paths` could name folders, in process. A folder is watched through a `Folder` setting `[AI]` | Folder settings cover the common case; a plugin that does not opt in costs nothing |
| WS-06 | Every open item is offered the reload when any of its watched files changed, not only when a file of the entry on screen did; a seat that may not change the workspace is not offered | The entry on screen is the window's view, not the backend's |
| WS-06, OVV-003, SPL-009 | [AI] A reload that fails (a file gone, a decoder or option refused) leaves the viewer playing its old Content and playhead, with a dismissible `Could not reload: <reason>` that returns for the next failure, and not when the files changed again meanwhile (the offer stands). The old stream plays while the files are read, with no loading cover. A file that resolves but then cannot be opened still fails in the viewer, with no old Content left. The reference said `entry N` and opened the media in the same step | Items resolve as a whole, not per entry, and opening the media is the stream's job |
| LV-01, LV-02 | [AI] A feed's failure or recovery reason is a short typed sentence, never the device's or RTSP's exception text; the reference showed that text | The text can carry the camera's address or login |
| LV-03, LIV-007 | [AI] Events go on arriving while a viewer is paused; the reference left them in a ten-document buffer that dropped the oldest | The Events list records what the camera sent, and the picture alone pauses |
| WS-09 | A bookmark row opens on click or Enter; the reference opened it on mouse press, with no keyboard | The row is a button, so the keyboard reaches it |
| WS-09 | The Bookmarks view has no footer line, and with no bookmark it shows no search, filter or Export CSV; the reference showed the line and a disabled button | Terse in-app text |
| WS-09 | Another workspace replacing the open one selects the Bookmarks view when it has bookmarks; a workspace the window starts with does not | A reload keeps the view the user chose |
| WS-10 | The save dialog suggests the file name only, in the dialog's own folder; the reference suggested the workspace's folder. A new CSV file is owner-only, like a workspace file. A target name, entry or note that starts with `=`, `+`, `-`, `@`, a tab or a carriage return is written with a leading `'`; the reference wrote cells as typed. A time exactly half a millisecond past a whole one rounds up; the reference's float formatting rounded those by binary representation (0.0625 s to 0.062, 0.1875 s to 0.188) | One native save dialog for every export. Notes come from every seat, and a spreadsheet would run such a cell as a formula. Times are whole microseconds, so a tie is exact and one rule covers every one |
| WS-11 | A viewer reveals the top-level rows of the item in the active pane, not the entry on screen, and a row closes when another pane becomes active even if its viewer stays open; the reference marked every open viewer's row | The window's view names one active viewer |
| WS-11 | Every view's sidebar keeps one least width, and a drag ends below half of it closes the sidebar; the reference used the shown view's own minimum | The views' content fits one least width |
| WS-11 | An audience without host details gets same-named rows numbered, with no folder or camera hint | The hint names the host's files and cameras |
| WS-11 | Search and Name sort fold case one code point at a time; Cherokee folds to small letters, not capitals, so it sorts differently among other scripts. Accepted | JavaScript has no `casefold`; the text matches either way |
| WSC-007 | [AI] A new live stream keeps its username and password, and the MQTT ones, exactly as typed, spaces included; the reference's dialog trimmed them when adding | A password may begin or end with a space |
| ADD-006 | [AI] A blank Camera Head lists the sizes of the configured head, as the stream will use it; the reference listed head 1 | The list is of the head the stream gets |
| LIV-008 | [AI] No other sources listed; Edit has them | A watcher may not see them |
| LOB-012, WSU-017 | [AI] Unhide and open unhides a lane and opens it, but leaves the lane's pane without the focus on that lane; the reference focused the lane | The window has no way to focus a lane yet |
| WS-02, WS-11, WS-12, CHR-020 | [AI] A recent shows its folder as a full path, not with `~`; the hover text of a tree row with no picture starts with its whole name (a row with a picture has none, as in the reference) | The page does not know the home folder; a cut-off name has no other full form, and a text tip would show beside the picture card |
| WS-15, WSU-016, LOB-013 | [AI] A hover picture is asked for again 1 s after the last request ended, not on a fixed timer, and its card is kept inside the window, not the screen | Requests never overlap; a page cannot draw outside its window |
| WSU-004, SPL-001 | [AI] The welcome rows hide their key chips below the `sm` breakpoint (a window near its least width at 125% zoom or more); the reference always drew them and elided the labels | Chips beside labels fail the fit check at 640x480 and 200% (the label is clipped and overlapped); the keys stay in the menus, the Keyboard Shortcuts dialog and the start panel's tooltips |
| LOB-006 | [AI] A scan that breaks says `The scan stopped unexpectedly.` and logs the detail; the reference showed the exception text on hover | A panic message is for developers, and the detail can name paths |
| LOB-008 | [AI] The Live footer leaves out the sign-in box and the logins below 20rem of window height, and a login's user and password sit one over the other at the sidebar's width, so about two logins show before the list scrolls (five where the Settings dialog has room); the reference kept the controls and showed five side by side | Settings edits the same two; a `$NAME` reference needs 24ch to show whole, which two fields do not leave in a sidebar |
| WS-07, WSC-012, WSC-A001 | [AI] A resolver's metadata shows in Information for playlists, entries and lanes (the reference's video metadata is the entry's); a nested object reads `key: value, …` | Python's dict `repr` is not the user's spelling |
